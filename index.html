01 · OVERVIEW

Introduction & Website Purpose

This report examines an online shopping website and one specific user task.

About the selected website

Website: Daraz Pakistan

URL: https://www.daraz.pk/

Daraz is an online shopping platform where customers can browse product categories, search for items, review product information and place orders. Sellers can also display products through the platform.

Main purpose: To make shopping and product discovery available online.

Intended users

  • Customers who want to shop online.
  • People comparing product prices and features.
  • Sellers who want to offer products online.
  • Users who prefer delivery rather than visiting shops.
Reason for selection

Daraz was selected because it provides useful examples of web programming concepts, including search, product pages, forms, filters, shopping-cart controls and responsive layouts.

TASK

Selected user task

Find a mobile phone, check its price and product details, and add it to the shopping cart.

Expected result: A user should be able to locate a relevant phone, understand its details and add it to the cart without unnecessary difficulty.

03 · VISUAL REVIEW

Visual Design Evaluation

Visual design includes colour, typography, spacing, imagery and the arrangement of information.

◒

Colour & contrast

Observe the orange and white brand presentation. Check whether text and buttons have enough contrast and whether highlighted areas compete for attention.

Aa

Typography

Check whether product names, prices, labels and descriptions are readable at normal viewing size.

▤

Spacing & alignment

Look for consistent gaps between product cards, headings, images and page sections.

▧

Images & icons

Product images should be clear and relevant. Icons should be recognizable and understandable.

☷

Consistency

Compare multiple pages to see whether navigation, buttons and typography follow a consistent visual style.

↗

Visual hierarchy

Check whether the most important information, such as product title and price, is easy to notice.

Five observations to verify on the live website

01 · Colour

Check whether orange highlights important actions clearly. Too many highlighted elements may distract users.

Possible improvement: use emphasis selectively.
02 · Text size

Check whether product details and labels are readable on desktop and mobile.

Possible improvement: maintain comfortable text sizes.
03 · Product images

Check whether product photos are clear and show useful views.

Possible improvement: provide consistent, high-quality images.
04 · Spacing

Check whether product cards and sections feel crowded.

Possible improvement: use consistent spacing.

Desktop layout

  • More horizontal space is available.
  • Several product cards may fit in one row.
  • Navigation can display more links.

Mobile layout

  • Content is arranged for a narrow screen.
  • Fewer product cards fit in each row.
  • Buttons need comfortable touch areas.

Accessibility checks

✓ Text readability and sufficient contrast.

✓ Meaningful labels for buttons and form fields.

✓ Alternative text for informative images.

✓ Keyboard navigation and visible focus indicators.

✓ No unintended horizontal scrolling or overlapping content.

Testing required

Compare the same Daraz page on a desktop and a mobile screen. Check keyboard focus, form labels and image alternative text where possible. These are investigation checks, not claims that a specific accessibility defect exists.

Forms & Interactive Features

Forms collect information. Interactive controls respond to user actions.

FORM EXAMPLE

Login form

A login form lets an existing user access an account. Common fields may include a phone number or email address and a password.

Demo only — no information is sent.

Validation: Empty or incorrectly formatted fields may produce an error. A website should also validate data on its server.

INTERACTIVE FEATURE 1

Product search

Action: User enters a product name and starts a search.

Page change: Matching products or a no-results message are displayed.

User benefit: Helps users locate products more quickly.

Possible JavaScript role: Read input, respond to the search action and update the interface.

Action: User selects Add to Cart on a product page.

Page change: The cart may update to show the selected product and quantity.

06 · WEB TECHNOLOGY

Client/Server Architecture & HTTP

The following is a proposed three-tier model for explaining how an online shopping website can work.

01

Presentation layer

Browser · HTML · CSS · JavaScript

Displays pages and receives user actions.
↕ Request / response
02

Application layer

Application server · Business logic

Processes requests and applies application rules.
↕ Read / write data
03

Database layer

Product · User · Order data

Stores and retrieves information.

Example: searching for a mobile phone

  1. The user enters a phone name in the browser.
  2. The browser sends a request to the website server.
  3. The application processes the search request.
  4. The application may retrieve matching product data from a database.
  5. The server sends a response to the browser.
  6. The browser displays the search results.

HTTP request and response

HTTP stands for Hypertext Transfer Protocol. A request is sent by a client to a server. The server returns a response that may contain the requested page or data.

GET and POST

GET: Commonly used to request information, such as product search results.

POST: Commonly used to submit information, such as registration or order data.

Client-side validation

Checks information in the browser and can give quick feedback before submission.

Server-side validation

Checks submitted information on the server. It remains important even if browser validation is present.

Cookies and sessions

Cookies can store small pieces of browser information. Sessions can help a website maintain information about a user's activity. Their exact use in Daraz should not be assumed without reliable evidence.

This diagram is a proposed educational architecture, not a verified description of Daraz's internal servers, programming language or database.

08 · FINAL REFLECTION

Conclusion & Personal Reflection

Conclusion

Daraz is an online shopping platform that gives users a way to browse products and shop online. This evaluation considers its website structure, navigation, visual design, responsiveness, forms and interactive features. The proposed redesign focuses on clearer navigation, easier product search, readable mobile layouts and well-organized product information.

This investigation also connects practical website behaviour with web programming concepts such as client/server architecture, HTTP, GET and POST, validation, cookies and sessions.

Three priority improvements

  1. Make product searching easier.
  2. Improve mobile readability and usability.
  3. Organize product information clearly.

Trade-off

Adding more product information may make a page longer. The redesign should balance useful detail with a simple layout.

Personal reflection

I learned that a good website is not only about writing HTML, CSS and JavaScript. It should also be easy to use, attractive, responsive and accessible. Examining a real website helped me connect web programming concepts with features that users interact with.
